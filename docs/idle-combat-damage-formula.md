# 放置戰鬥傷害公式與同步設計

## 目的

這份文件記錄 Unity 放置版戰鬥後續要採用的傷害計算方向，以及目前 BeiDou 後端在一般地圖戰鬥中的責任邊界。

參考資料：

- MapleStory 傷害公式參考：https://wiki.biligame.com/maplestory/%E6%B8%B8%E6%88%8F%E4%BC%A4%E5%AE%B3%E5%85%AC%E5%BC%8F
- 參考頁面顯示最後編輯日期：2022-10-31

## 目前後端是否計算傷害

目前一般地圖戰鬥不是完整的 server-authoritative 傷害模式。

在 `AbstractDealDamageHandler` 流程中：

1. Client 攻擊封包會帶上怪物 OID、技能、hit 次數與每 hit 傷害數字。
2. Server 會依角色狀態、技能、buff、怪物資料推估 `calcDmgMax`。
3. Server 用 `maxWithCrit` 等上限做傷害合法性檢查，避免明顯 damage hack。
4. Server 最後仍是把 client 回報的傷害套用到怪物 HP。

所以現在的一般戰鬥可視為「client 回報傷害，server 驗證上限後套用」，不是所有傷害都由 server 自行計算。

放置戰鬥應該改成 server-authoritative：Unity 只負責顯示與送出進入、離開、領取等操作，不送 hit 傷害；server 每 10 秒計算放置進度、EXP、楓幣與掉落，再推送狀態給 client。

## 放置戰鬥同步流程

放置戰鬥進入後，server 每 10 秒主動推送目前狀態：

1. 計算距離上次 tick 的經過時間。
2. 依角色能力、技能、怪物資料與傷害公式計算可擊殺數。
3. EXP 與楓幣直接發給角色，不進 pending。
4. EXP 與楓幣沿用既有 `STAT_CHANGED` 封包同步給 client。
5. 道具掉落維持 pending rewards，等待玩家領取或後續設計成背包可放入時再處理。
6. 送出 `IDLE_STAGE_RESULT` 給 client 更新放置面板。

## MapleStory 傷害公式拆解

以下拆成適合後端實作的計算階段。實際落地時應建立獨立的 server-side 計算器，避免讓 Unity 參與權威傷害計算。

### 總屬性

角色主屬性可能是 STR、DEX、INT、LUK。

```text
基礎總屬性 = 裸屬性 + floor(附加屬性)
總屬性 = floor(基礎總屬性 * (1 + 百分比屬性 / 100)) + 最終屬性
```

資料來源應包含：

- 裸屬性：角色 AP、升級、職業基礎屬性。
- 附加屬性：裝備、技能、buff 提供的固定屬性。
- 百分比屬性：潛能、裝備、技能、buff 提供的百分比屬性。
- 最終屬性：不再吃百分比屬性的最後加成。

### 總攻擊

物理職業使用總攻擊，魔法職業使用總魔攻。公式結構相同：

```text
總攻擊 = floor(floor(附加攻擊) * (1 + 百分比攻擊 / 100)) + 最終攻擊
```

資料來源應包含：

- 附加攻擊：武器、裝備、技能、buff 的固定攻擊。
- 百分比攻擊：潛能、裝備、技能的攻擊百分比。
- 最終攻擊：不再吃百分比攻擊的最後加成。

### 面板最大傷害

單手、雙手、物理、魔法職業會依主屬性、副屬性與武器係數計算面板：

```text
最大面板 =
((總主屬性 * 4) + (總副屬性 * 1))
* 武器係數
* 總攻擊 / 100
```

主副屬性與武器係數需要依職業與武器類型建立對照表。

### 單 hit 傷害

放置戰鬥不需要真的模擬每一次動畫 hit，但底層仍應把單 hit 的因素拆出來：

- 技能倍率。
- 傷害百分比。
- 對一般怪物傷害。
- Boss 傷害。
- 最終傷害。
- 熟練度造成的最低傷害浮動。
- 無視防禦。
- 怪物防禦率。
- 屬性抗性與弱點。
- 爆擊率與爆擊傷害。
- 等級差距修正。
- 星力、祕法、真實之力等地圖需求修正。

建議概念式：

```text
基礎單 hit 最大傷害 = 最大面板 * 技能倍率
傷害加成後 = 基礎單 hit 最大傷害 * (1 + 傷害% + 一般怪物傷害% 或 Boss傷害%) / 100
最終傷害後 = 傷害加成後 * Π(1 + 各來源最終傷害% / 100)
防禦後 = 最終傷害後 * 防禦係數
屬性後 = 防禦後 * 屬性倍率
爆擊期望 = 屬性後 * 爆擊期望係數
等級修正後 = 爆擊期望 * 等級差距倍率
```

一般怪物傷害與 Boss 傷害不可混用，應依怪物類型決定套用哪一組。

### 防禦與無視防禦

```text
有效防禦率 = 怪物防禦率 * (1 - 總無視防禦率)
防禦係數 = max(0, 1 - 有效防禦率)
```

無視防禦通常不是單純加總，後續實作時需要依遊戲版本資料決定是否採用乘法疊加。

### 爆擊期望

放置戰鬥可以先使用期望值，避免每 10 秒大量擲骰造成結果抖動：

```text
爆擊期望係數 = (1 - 爆擊率) * 1 + 爆擊率 * (1 + 平均爆擊傷害)
```

若未來要做戰鬥 log 或更接近原版的命中表現，可再改成逐 hit 隨機。

## 建議實作：IdleCombatDamageCalculator

後續建議新增 `IdleCombatDamageCalculator`，專責放置戰鬥 server-side 傷害。

輸入：

- `Character chr`
- 怪物資料
- `IdleStageConfig stage`
- 預設技能或職業對應技能

輸出：

- 每秒平均傷害 DPS。
- 每 10 秒可擊殺怪物數。
- 每 10 秒取得的 EXP、楓幣與掉落機率結果。

實作順序：

1. 讀取角色 STR/DEX/INT/LUK 與物攻、魔攻。
2. 建立職業主副屬性與武器係數對照。
3. 先用普通攻擊或預設技能計算面板傷害。
4. 套用怪物防禦、等級差距、一般怪物傷害。
5. 用期望爆擊計算平均單 hit 傷害。
6. 依怪物 HP 計算每秒與每 10 秒擊殺數。
7. 依擊殺數發放原始怪物 EXP、楓幣，並計算原始掉落表。

## 當前結論

- 放置戰鬥傷害應由 server 計算，client 不回報傷害。
- EXP 與楓幣不做 pending，擊殺結算時直接給角色。
- 道具因為背包格數、不可交易、任務道具、裝備隨機屬性等規則較複雜，暫時維持 pending。
- 傷害公式要分階段實作，不要一次塞成單一巨大公式，否則很難比對角色能力、裝備、技能與怪物防禦問題。
