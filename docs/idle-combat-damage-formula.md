# 放置戰鬥傷害公式與同步設計

## 目的

這份文件記錄 Unity 放置版戰鬥後續要採用的傷害計算方向，以及目前 BeiDou 後端在一般地圖戰鬥中的責任邊界。

參考資料：

- MapleStory 傷害公式參考：https://wiki.biligame.com/maplestory/%E6%B8%B8%E6%88%8F%E4%BC%A4%E5%AE%B3%E5%85%AC%E5%BC%8F
- 參考頁面顯示最後編輯日期：2022-10-31

## 目前後端是否計算傷害

目前一般地圖戰鬥不是完整的 server-authoritative 傷害模式。

在 `AbstractDealDamageHandler` 流程中：

1. Client 攻擊封包會帶上怪物 OID、技能、hit 次數與每 hit 傷害數字。
2. Server 會依角色狀態、技能、buff、怪物資料推估 `calcDmgMax`。
3. Server 用 `maxWithCrit` 等上限做傷害合法性檢查，避免明顯 damage hack。
4. Server 最後仍是把 client 回報的傷害套用到怪物 HP。

所以現在的一般戰鬥可視為「client 回報傷害，server 驗證上限後套用」，不是所有傷害都由 server 自行計算。

放置戰鬥應該改成 server-authoritative：Unity 只負責顯示與送出進入、離開、領取等操作，不送 hit 傷害；server 每 10 秒計算放置進度、EXP、楓幣與掉落，再推送狀態給 client。

## 放置戰鬥同步流程

放置戰鬥進入後，server 每 10 秒主動推送目前狀態：

1. 計算距離上次 tick 的經過時間。
2. 依角色能力、技能、怪物資料與傷害公式計算可擊殺數。
3. EXP、楓幣與道具掉落直接發給角色，不進 pending。
4. EXP 與楓幣沿用既有 `STAT_CHANGED` 封包同步給 client。
5. 道具掉落在同一次 tick 先檢查背包空間，成功後直接寫入背包；封包回傳本輪取得清單。
6. 送出 `IDLE_STAGE_RESULT` 給 client 更新放置面板。

## MapleStory 傷害公式拆解

以下拆成適合後端實作的計算階段。實際落地時應建立獨立的 server-side 計算器，避免讓 Unity 參與權威傷害計算。

### 總屬性

角色主屬性可能是 STR、DEX、INT、LUK。

```text
基礎總屬性 = 裸屬性 + floor(附加屬性)
總屬性 = floor(基礎總屬性 * (1 + 百分比屬性 / 100)) + 最終屬性
```

資料來源應包含：

- 裸屬性：角色 AP、升級、職業基礎屬性。
- 附加屬性：裝備、技能、buff 提供的固定屬性。
- 百分比屬性：潛能、裝備、技能、buff 提供的百分比屬性。
- 最終屬性：不再吃百分比屬性的最後加成。

### 總攻擊

物理職業使用總攻擊，魔法職業使用總魔攻。公式結構相同：

```text
總攻擊 = floor(floor(附加攻擊) * (1 + 百分比攻擊 / 100)) + 最終攻擊
```

資料來源應包含：

- 附加攻擊：武器、裝備、技能、buff 的固定攻擊。
- 百分比攻擊：潛能、裝備、技能的攻擊百分比。
- 最終攻擊：不再吃百分比攻擊的最後加成。

### 面板最大傷害

單手、雙手、物理、魔法職業會依主屬性、副屬性與武器係數計算面板：

```text
最大面板 =
((總主屬性 * 4) + (總副屬性 * 1))
* 武器係數
* 總攻擊 / 100
```

主副屬性與武器係數需要依職業與武器類型建立對照表。

### 單 hit 傷害

放置戰鬥不需要真的模擬每一次動畫 hit，但底層仍應把單 hit 的因素拆出來：

- 技能倍率。
- 傷害百分比。
- 對一般怪物傷害。
- Boss 傷害。
- 最終傷害。
- 熟練度造成的最低傷害浮動。
- 無視防禦。
- 怪物防禦率。
- 屬性抗性與弱點。
- 爆擊率與爆擊傷害。
- 等級差距修正。
- 星力、祕法、真實之力等地圖需求修正。

建議概念式：

```text
基礎單 hit 最大傷害 = 最大面板 * 技能倍率
傷害加成後 = 基礎單 hit 最大傷害 * (1 + 傷害% + 一般怪物傷害% 或 Boss傷害%) / 100
最終傷害後 = 傷害加成後 * Π(1 + 各來源最終傷害% / 100)
防禦後 = 最終傷害後 * 防禦係數
屬性後 = 防禦後 * 屬性倍率
爆擊期望 = 屬性後 * 爆擊期望係數
等級修正後 = 爆擊期望 * 等級差距倍率
```

一般怪物傷害與 Boss 傷害不可混用，應依怪物類型決定套用哪一組。

### 防禦與無視防禦

```text
有效防禦率 = 怪物防禦率 * (1 - 總無視防禦率)
防禦係數 = max(0, 1 - 有效防禦率)
```

無視防禦通常不是單純加總，後續實作時需要依遊戲版本資料決定是否採用乘法疊加。

### 爆擊期望

放置戰鬥可以先使用期望值，避免每 10 秒大量擲骰造成結果抖動：

```text
爆擊期望係數 = (1 - 爆擊率) * 1 + 爆擊率 * (1 + 平均爆擊傷害)
```

若未來要做戰鬥 log 或更接近原版的命中表現，可再改成逐 hit 隨機。

## 已實作：IdleCombatDamageCalculator

目前已新增 `IdleCombatDamageCalculator`，專責放置戰鬥 server-side 傷害。`IdleCombatCalculator` 不再用自訂 power ratio 決定擊殺數，而是用公式推導：

```text
每次攻擊期望傷害 = IdleCombatDamageCalculator.calculateExpectedDamagePerAttack(...)
本輪總傷害 = 上輪未打完傷害 + 每次攻擊期望傷害 * 攻擊次數
擊殺數 = floor(本輪總傷害 / 平均怪物 HP)
剩餘傷害 = 本輪總傷害 - 擊殺數 * 平均怪物 HP
```

剩餘傷害保存在 `IdleCombatSession.carriedDamage`，所以如果角色 10 秒內打不死怪，傷害不會歸零，下一次 server 主動推送時會繼續累積。

輸入：

- `Character chr`
- 怪物資料
- `IdleDamageContext`

輸出：

- 每次攻擊期望傷害。
- 角色目前面板戰力 `playerPower`，目前用最大屬性攻擊力表示。

### 目前已套用的係數

- 總主屬性、總副屬性：讀取 `Character.getTotalStr/Dex/Int/Luk()`。
- 物理攻擊、魔法攻擊：讀取 `Character.getTotalWatk()`、`Character.getTotalMagic()`。
- 武器係數：有裝備武器時讀取 `ItemInformationProvider.getWeaponType()`；沒裝備時依職業給預設武器。
- 魔法職業：用 INT 作主屬性、LUK 作副屬性，套用武器係數與總魔攻。
- 物理職業：沿用後端既有 `Character.calculateMaxBaseDamage()`，它會依武器係數、主副屬性與總物攻計算最大面板。
- 技能倍率：由 `IdleDamageContext.skillPercent` 帶入，預設 100%。
- 熟練度：用最大面板與最小面板取期望值，預設熟練度 20%。
- 傷害%、普通怪物傷害%、Boss 傷害%：依怪物是否 Boss 決定套用普通怪或 Boss 傷害，並與傷害%加法疊加。
- 最終傷害：用乘法係數 `finalDamageMultiplier`。
- 怪物防禦與無視防禦：用怪物物防/魔防資料推導防禦率，再套用無視防禦。
- 屬性抗性：套用 `IMMUNE = 0`、`STRONG = 0.5`、`NORMAL/NEUTRAL = 1.0`、`WEAK = 1.5`。
- 爆擊期望：用爆擊率與爆擊傷害算期望倍率。
- 等級差距：角色高於怪物時最多 +20%，角色低於怪物時最低保留 10%。
- 星力地圖修正：保留 required/character 欄位並套用未達標懲罰。
- 祕法與真實之力修正：依 0%、10%、30%、50%、70%、100%、110%、130%、150% 區間套用。

### 目前仍是預設值的係數

這些不是公式漏做，而是目前後端放置流程還沒有對應資料來源。`IdleDamageContext` 已保留欄位，後續接技能、潛能、超級屬性、地圖需求時可以直接帶入：

- 技能倍率目前預設 100%，尚未依職業選放置技能。
- 傷害%、普通怪物傷害%、Boss 傷害%、最終傷害目前預設 0% 或 1.0 倍。
- 無視防禦目前預設 0%。
- 爆擊率與爆擊傷害目前預設 0%。
- 星力、祕法、真實之力目前預設沒有地圖需求，因此倍率為 1.0。
- 現代版潛能、附加潛能、超級屬性、聯盟、內在能力等資料目前不在這個後端資料模型內，不能硬捏數字。

## 當前結論

- 放置戰鬥傷害已改由 server 計算，client 不回報傷害。
- EXP、楓幣與道具不做 pending，擊殺結算時直接給角色。
- 道具會先整批檢查背包空間，再用既有背包新增流程發放；任務道具與 PQ 道具仍排除。
- 傷害公式已拆成可逐項驗證的計算器；後續重點是補齊技能選擇與角色進階屬性資料來源，而不是再改放置主流程。
